# 範圍與各模組

## 本次計畫的邊界

- 已確認下一模組為通道品質；此次授權是建立剩餘專案的排程與估算，再討論，尚未授權逐一實作以下工作包。
- 已完成的拓樸作為起點：1 Donor、5 IAB Nodes、每 Node 1 UE、多個 Tags；平面靜態位置、固定 seed、幾何三區與非均勻配額。
- 首版沿用：所有服務 t=0 開始，輪長取最晚期限；DU Window 固定 600 ms，但起點／間隔尚未定。成功認列採 `t < deadline`。
- 近區 SNR 優於遠區，先限同 Node／同 Window；同一 Window 的 SNR 固定，下個 Window 更新。自身殘餘 CW 自干擾假設為 0 W；這些是研究假設。
- 不新增移動、交遞、完整回傳協定、動態 BD／SFS 最佳化、CLM 重訓或多輪服務。若後續需要，另行定範圍及估算。

來源：[R-01 最新第 27–32 節](../ReferDoc/Plan/R-01_System_Model_and_Baseline_Decision_Record.md)、[交接規格](../ReferDoc/Plan/Codex_Handoff_Specification_Ambient_IoT_DES.md)、[已交付拓樸](../src/iab/)。舊文件中的「尚未實作」與早期多週期排序是歷史狀態；以已交付拓樸及較後決策為準。

### 共用契約如何漸進加入

- W01 僅補它需要的最小欄位，不讓整套 Config 討論阻擋通道原型。
- W02 從既有 [src/iab/contracts.py](../src/iab/contracts.py) 整理共用入口；**維持 Config／DTO 集中一個 `.py`**，不替每個模組複製一份。
- 該檔目前位於 iab；是否改成中立的共用路徑，在 W02 交一份相容的搬移草案討論，不在排程階段先搬。
- W03～W09 依已接受的資料形狀增加本模組必要欄位，內部可變狀態仍留各模組。
- 情境測試與輸出紀錄從各模組起就建立；W10 負責整合，不等到最後才補測試或追蹤。
