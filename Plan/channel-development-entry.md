日期：2026-10-29。

本文件將剩餘確認集中處理。
不再逐欄詢問命名及例行工程選擇。

已接受的測試配置見[開發起始表](channel-entry-pack.md)。
Notebook已人工接受；核心已抽離至src/channel/。

## 1. 必要項目

| 項目 | 需要確認什麼 | 準備方式 |
|---|---|---|
| 最小測試配置 | 三檔CW功率、參考增益、路損指數、beta、噪聲、干擾及帶寬／符號率 | 代理先交一份完整候選表。每值標單位、來源及測試用途。使用者集中檢視。 |
| 有效距離與超界處理 | 參考距離模型在多近的範圍使用。低於有效距離時如何處理。 | 提出明確方案，說明拒絕輸入或限制增益的影響。不移動既有Tag。 |
| FBL輸入及本模組驗收 | 初版使用哪些k／n案例。何時算本模組可接受。 | 明列案例、預期值及限制。先驗證公式及資料綁定，再做正式PHY校準。 |

### 測試配置須包含的說明

- 頻段若用來算參考增益，也須明列。
- 跨Node共同因子的關係須明列。
- 接收抽樣與通道抽樣使用不同亂數來源。
- 同窗SNR固定，不代表每包結果相同。
- 隨機類的逐包抽樣假設須明列。
- 成功／失敗類仍依已接受的功率表判定。
- 數值須避免隨機類只剩數值上的0或1。
- 不以未經說明的機率夾值掩蓋問題。

以上由代理整理候選配置。
未確認的預設不冒稱已定案。

## 2. 建議的第一版邊界

- 讀取已接受的拓樸快照。
- 系統明列Window ID及CW檔位。
- 本模組計算接收功率、SNR及SINR。
- 同Node每窗抽一次±3dB偏移。
- 本模組按功率表選接收類別。
- FBL測試直接輸入k與n。
- 隨機類使用FBL掉包率。
- 輸出完整的功率／鏈路解釋資料。
- 不在本模組產生完整UE／DU時間表。
- 不在本模組提交能量或服務計帳。

k是資訊bit數。
n是資料碼字的通道使用次數。
兩者必須符合BPSK模型的單位約定。
此輸入方式是首版測試替代。
不宣稱已完成正式TBS映射。

## 3. 建議的最小驗收

| 情境 | 預期檢查 |
|---|---|
| 同一Window重複讀取 | SNR／SINR及偏移相同 |
| 下一Window | 更新通道；保持已定的變化要求 |
| 相同配置及seed重跑 | 結果可重現 |
| 同Node近區與遠區 | 品質排序符合已定假設 |
| 三檔功率×三區 | 接收類別符合功率表 |
| 相同類別、不同距離 | 原始SNR／SINR仍依距離計算 |
| 指定k／n及品質 | FBL結果能與獨立參考值比對 |
| 成功／失敗類 | 區分原始FBL估計與最終0／1 |
| 無效配置 | 明確拒絕，不輸出部分有效結果 |
| 距離超界 | 依接受的規則處理，座標不變 |

測試通過不等於人工接受。
Notebook仍需逐段導讀。
接受後才抽離本模組.py。

## 4. 可延後的工作

- 正式戶外RF校準與實測比對。
- 完整TBS／CRC／編碼／SFS到k／n及時間的映射。
- 實際批次傳送的能量與時間可行性。
- ResourceTimeline、Engine與CLM整合。

這些工作保留在對應模組。
它們不阻擋明標測試輸入的原型。
本模組也不替它們作未驗證的保證。

## 5. 進入開發的方式

1. 代理準備完整測試配置與距離邊界方案。
2. 使用者集中檢視模型假設及測試配置。
3. 將本模組範圍與驗收納入OpenSpec。
4. 依workflow啟動Notebook與情境測試。
5. 審查及更新圖、code-trace後，進行人工導讀。
