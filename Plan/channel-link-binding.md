# 功率表與通道鏈路的綁定

日期：2026-10-29。狀態：設計說明，尚未實作。

使用者已選功率表優先。
本文件說明每個接收結果如何追溯。
欄位名稱是設計草案。
Config／DTO仍集中於同一個.py。

## 1. 一條鏈路如何識別

每條鏈路對應一個Node及其所屬Tag。
每個Window各有一份通道快照。

| 識別資料 | 用途 |
|---|---|
| Node ID | 指出接收器 |
| Tag ID | 指出回傳來源 |
| Window ID | 指出哪一窗的通道 |
| 實際距離 | 計算傳播增益 |
| TagZone | 選擇功率表中的分區 |

同窗內不重新抽取通道。
批次可讀取同一份通道快照。
不同TBS仍可能有不同的FBL錯誤率。

## 2. 功率檔不能只有名稱

每個檔位須綁定實際功率。
各檔位須引用同一版通道設定。
比較功率時，其他條件須可對照。

| CW檔位 | 實際功率 | 通道設定 | 近區 | 中區 | 遠區 |
|---|---|---|---|---|---|
| LOW | P_L，待定 | 相同設定版本 | 成功 | 隨機 | 失敗 |
| MEDIUM | P_M，待定 | 相同設定版本 | 成功 | 成功 | 隨機 |
| HIGH | P_H，待定 | 相同設定版本 | 成功 | 成功 | 成功 |

- 實際功率須滿足0 < P_L < P_M < P_H。
- 功率先以線性單位計算。
- dBm僅作輸入／顯示時的明確換算。
- 系統以一份檔位定義取得功率及規則。
- 不另保留可互相矛盾的功率標籤與數值。
- 未知檔位或缺少功率時，配置檢查失敗。
- 同Window不得改換CW檔位。
- 下一窗可由系統指定其他檔位。

## 3. 通道設定綁定哪些內容

| 設定群 | 內容 |
|---|---|
| 傳播 | 參考距離、參考增益、單程路損指數及有效範圍 |
| Tag | 共用反射功率係數beta |
| 接收器 | 噪聲、帶寬及每Node固定外部干擾 |
| 窗級變動 | seed、±3dB均勻偏移及分窗更新規則 |
| 接收規則 | 已接受的功率×幾何區表及其版本 |
| Access參照 | 合法TBS、編碼、SFS及k／n映射的版本 |

- 此處只列設定責任，不新增實體數值。
- 各Node的固定干擾值須可追溯。
- 不以改噪聲或增益來偷偷補償功率檔位。
- 如需更換通道設定，須保存新的配置版本。

## 4. 接收功率如何綁定

\[
P_{\mathrm{rx},j,k,w}
=P_{\mathrm{CW}}(\mathrm{profile})\,
\beta\,g_0^2(d_k/d_0)^{-2\eta}\,
10^{\delta_{j,w}/10}.
\]

- 檔位提供P_CW。
- 拓樸提供距離及分區。
- 通道設定提供beta、g0、d0及eta。
- 當窗快照提供共同偏移delta。
- 接收器設定提供噪聲與外部干擾。
- 接著計算SNR與SINR。
- FBL輸入還需換成匹配BPSK的每次使用品質。

詳細公式及適用限制見[文獻依據](channel-formula-evidence.md)。

## 5. 最終掉包率如何綁定

先查功率表，取得接收類別。
再依類別產生實際使用的掉包率。

| 接收類別 | 實際使用的掉包率 | 判定依據 |
|---|---|---|
| 成功 | 0 | 功率表的理想化規則 |
| 失敗 | 1 | 功率表的理想化規則 |
| 隨機 | epsilon_FBL(rho,k,n) | 實際鏈路品質與有限碼長近似 |

- 系統仍計算可用的原始FBL估計。
- 系統分開保存原始估計與最終機率。
- 若缺少合法k／n，不得編造FBL值。
- 成功類的0不表示FBL公式恰好算出0。
- 失敗類的1也不冒稱物理推導值。
- 隨機類不因檔位名稱而改寫SNR。
- 數值算成不合法機率時，應報告原因。
- 不默默夾成任意設定的機率。

## 6. 同一Tag的對照例

假設Tag-012屬於Node-2的中區。
以下只用符號，不填正式功率值。

| Window | 系統檔位 | 實際功率 | 實算品質 | 接收類別 | 最終掉包率 |
|---|---|---|---|---|---|
| W1 | LOW | P_L | rho_1 | 隨機 | epsilon_FBL(rho_1,k,n) |
| W2 | MEDIUM | P_M | rho_2 | 成功 | 0 |

- W2的成功來自MEDIUM×中區規則。
- rho_2仍由P_M及當窗通道計算。
- 系統不修改rho_2來製造成功。
- 此例不表示所有run都依低→中排列。
- 能量、時間及接入條件仍須成立。

## 7. 每次接收的解釋資料

| 要回答的問題 | 應保留資料 |
|---|---|
| 哪個Tag向哪個Node傳送？ | Node、Tag、Window及批次／傳送識別 |
| 為何使用此功率？ | 系統配置來源、檔位與實際CW功率 |
| 為何得到此品質？ | 距離、通道設定版本、偏移、接收功率、噪聲及干擾 |
| 有限碼長如何計算？ | TBS、k、n、品質正規化及FBL模型版本 |
| 為何使用此掉包率？ | 幾何區、接收類別、原始FBL估計及最終機率 |
| 本次為何成功或失敗？ | 判定原因；隨機類另保留對應抽樣依據 |

這些資料供研究追蹤及驗收。
未來通道狀態仍不得提供給Policy。

## 8. 如何檢查綁定確實有效

1. 固定距離、偏移及接收器條件。
2. 用三個獨立校準案例比較功率檔。
3. 核對實算品質隨功率增加。
4. 核對接收類別符合已接受的表格。
5. 分開檢查原始FBL估計與最終機率。
6. 再測±3dB邊界及合法TBS範圍。
7. 保存配置、來源及差異原因。

- 校準案例共用偏移，不表示同窗改CW。
- 跨窗比較還須考慮兩窗偏移的差值。
- 該差值可在-6至+6dB之間。
- 固定其他條件時，功率檔差會和它相加。
- 若要跨窗實算品質必定改善，需另驗證檔差。
- 不因名稱為MEDIUM就宣稱實算品質必定較高。

綁定能讓結果可追溯。
模型可信度仍需要校準。
原始FBL與表格差異很大時，須揭露差異。
不能只因最終0／1符合表格就宣稱物理驗證通過。
校準可接受的BLER範圍仍待確認。
