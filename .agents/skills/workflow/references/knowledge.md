# Project closeout and interview learning

Reconcile the OpenSpec tech_improve.md statuses, source/archive locations and
validation links through [technical-debt.md](technical-debt.md). Keep accepted
deferrals distinct from resolved improvements and do not move backlog entries
into active changes without an approved implementation scope.

For new workflows, bounded project-data maintenance is included in the approved
workflow scope. After all changes merge and project acceptance is satisfied,
update project README navigation, interview index/status, summaries and verified
links in place. Use PARA as navigation categories, not as a bulk move plan.
OpenSpec alone follows its archive procedure. This is a project-end event, not
a background timer. Tag policy and cross-project profile sharing remain deferred.

Read only relevant project indexes, changed records and their original sources.
Reuse existing owners and update only justified content. If nothing changed,
record no-change rather than inventing pages. Preserve historical interview
answers and raw evidence; append dated corrections and superseding decisions.

## Included closeout

1. Verify original/archive/spec/diagram/trace locations and actual merge evidence.
   Root README links current goals/work, ongoing responsibilities, reusable
   resources and historical deliveries. Repair known stale links and report gaps.
2. Update interview/README.md and each completed workflow's status/delivery links.
   Summarize explicit preferences with source/date/scope; inferred concerns stay
   [Needs Verification], include counterevidence, and add no silent requirement.
3. Invoke bundled llm-wiki capture with bounded change/interview evidence and
   this workflow's existing closeout authorization. It updates existing source,
   pattern/index/log owners and hands each completed update to skill-evolution
   assess once. No extra routine curation or assessment approval is needed.
4. Report navigation changes, evidence, learning status and any pending assessment.
   Missing required closeout evidence blocks whole-workflow completion, not a
   factual statement that an individual PR has merged. Candidate evaluation can
   remain pending when no suitable independent task exists.

Explicit preferences can guide the current project's next interview immediately;
changing a reusable skill still uses its qualification, isolated comparison and
exact-version/target activation rules. Never write global user memory, scan
unrelated projects or activate a shared skill as a side effect of this closeout.
Keep independent events distinct and preserve unsuccessful findings.

## Existing optional-offer history

Do not rewrite past consent or legacy completed counts. A legacy workflow whose
closeout contract was optional retains knowledge_offer pending/accepted/declined
until an explicit current request settles it. For a new workflow with included
closeout, record pending then accepted using the existing request authorization,
and done after curation/assessment returns its result. Preserve a genuine current
user refusal and explain its effect on the remaining completion scope.

The local llm-wiki skill needs no external desktop application. Never execute
course/sources snapshots as current policy. Promotion/evaluation feedback returns
to the originating log without recursively starting another assessment.
